# Документация REST API

## Аутентификация
Все запросы, кроме получения публичных справочников, требуют аутентификации через сессию Django и передачи CSRF-токена в заголовке `X-CSRFToken`.

## Основные эндпоинты

### 1. Категории (Categories)
| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/categories/` | Получение списка категорий |

### 2. Заявки (Tickets)
| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/tickets/` | Получение списка своих заявок (фильтр: `?status=...`) |
| POST | `/api/tickets/` | Создание новой заявки |
| PATCH | `/api/tickets/{id}/` | Изменение заявки (валидация переходов статусов) |
| DELETE | `/api/tickets/{id}/` | Удаление заявки |

### 3. Бронирование (Bookings)
| Метод | URL | Назначение |
|---|---|---|
| GET | `/bookings/api/rooms/` | Получение списка комнат |
| GET | `/bookings/api/bookings/` | Получение списка своих броней (фильтры: `?status=...`, `?room=...`) |
| POST | `/bookings/api/bookings/` | Создание новой брони |
| PATCH | `/bookings/api/bookings/{id}/` | Редактирование брони (например, изменение цели) |
| DELETE | `/bookings/api/bookings/{id}/` | Удаление брони |
| POST | `/bookings/api/bookings/{id}/approve/` | Подтверждение брони (транзакция: меняет статус и флаг комнаты) |
| POST | `/bookings/api/bookings/{id}/complete/` | Завершение брони (освобождает комнату) |
| POST | `/bookings/api/bookings/{id}/reject/` | Отклонение брони |
| GET | `/bookings/api/bookings/{id}/history/` | Получение истории событий конкретной брони |

## Примеры операций

### Создание заявки (POST)
- URL: `POST /api/tickets/`
- Тело запроса: 
  ```json
  {
    "title": "Не работает принтер",
    "description": "Принтер в кабинете 301 не печатает",
    "category": 1
  }
- Успех: HTTP 201 Created, JSON созданного объекта. Владелец (owner) назначается сервером автоматически.
- Ошибки: 400 (название менее 5 символов, невалидная категория), 403 (не авторизован).
### Изменение статуса заявки (PATCH)
- URL: PATCH /api/tickets/5/
- Тело запроса: {"status": "progress"}
- Успех: HTTP 200, JSON обновлённого объекта.
- Ошибки: 400 (недопустимый переход статуса, например, сразу из new в done), 404 (объект не найден или не принадлежит текущему пользователю).
### Удаление заявки (DELETE)
- URL: DELETE /api/tickets/5/
- Успех: HTTP 204 No Content.
- Ошибки: 404 (объект не найден или не принадлежит пользователю).
### Подтверждение брони (POST)
- URL: POST /bookings/api/bookings/1/approve/
- Тело запроса: Пустое (действие инициируется фактом запроса).
- Успех: HTTP 200, {"status": "approved", "message": "Бронирование подтверждено"}.
- Ошибки: 400 (статус не "created" или комната уже занята).
- Бизнес-логика: Выполняется в транзакции (@transaction.atomic). Если обновление комнаты не удастся, статус брони не изменится.
### Редактирование цели (PATCH)
- URL: PATCH /bookings/api/bookings/1/
- Тело запроса: {"purpose": "Новая цель бронирования"}
- Успех: HTTP 200, JSON обновлённого объекта.
- Ошибки: 400 (цель менее 10 символов), 403/404 (бронь не принадлежит пользователю).
